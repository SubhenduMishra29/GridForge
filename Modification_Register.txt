    Application transaction rollback state integrity.

    Transaction lifecycle required explicit distinction between open,

    after a committed transaction.

GF-INT-042
======================================================================

Scope:
    Application command transaction/history commit boundary.

Finding:
    PRE-COMMIT, COMMIT and POST-COMMIT behavior required explicit
    separation so that post-commit history failure cannot roll back already
    committed Core state.

    CommandManager executes handler work before commit, obtains the

    A post-commit history-recording failure marks the command boundary
    degraded instead of attempting to roll back committed Core state.

Architectural requirement:
    Core transaction commit is authoritative; history recording is a
    post-commit application concern.
