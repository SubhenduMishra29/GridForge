Architectural authority
-----------------------

MainWindow
    owns the overall Qt dock-area/layout infrastructure.

Workspace/Layout
    owns the logical arrangement of editors/panels.

WorkspacePlacement
    owns canonical logical placement.

WorkspaceRealizer
    translates Workspace layout decisions into MainWindow operations.

PanelsPlugin
    owns panel composition and panel presentation capabilities.

PanelRegistry
    owns panel registration.

PanelManager
    owns panel runtime lifecycle.

PanelInstance
    owns runtime panel lifecycle.

PanelState
    owns panel lifecycle state only.

PanelDescriptor
    describes panel metadata/capabilities only.

Critical invariant
------------------

PanelSpec / PanelDescriptor / PanelState MUST NOT independently define
the canonical logical Workspace area.

Workspace/Layout is the sole authority for editor/panel arrangement.

GF-INT-040
======================================================================

Scope:
    Application transaction rollback state integrity.

Finding:
    Transaction lifecycle required explicit distinction between open,
    committing, committed, rolling back, rolled back and rollback-failed
    states.

Correction:
    Transaction records undo operations only while OPEN; commit creates the
    immutable undo journal; rollback transitions through ROLLING_BACK,
    attempts inverse operations, and represents rollback failure explicitly
    while preserving the first rollback error.

Architectural requirement:
    Rollback is a pre-commit transaction concern and cannot be repeated
    after a committed transaction.

    Application undo/redo history transition.

Architectural requirement:
    CommandManager owns undo-operation execution and transition

GF-INT-042
======================================================================

Scope:
    Application command transaction/history commit boundary.

Finding:
    PRE-COMMIT, COMMIT and POST-COMMIT behavior required explicit
    separation so that post-commit history failure cannot roll back already
    committed Core state.

Correction:
    CommandManager executes handler work before commit, obtains the
    immutable UndoJournal at commit, and records history only after commit.
    A post-commit history-recording failure marks the command boundary
    degraded instead of attempting to roll back committed Core state.

Architectural requirement:
    Core transaction commit is authoritative; history recording is a
    post-commit application concern.

Status:
    REMEDIATED — VERIFICATION DEFERRED

    Runtime/tests/CI verification deferred.
