> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Establish one deterministic engineering-to-per-unit boundary for Line, Cable, and Transformer studies, complete detached study preparation, and reconcile downstream Power Flow, Short Circuit, Protection, Dynamics, persistence, and compatibility consumers without duplicating GridForge architecture.

**Architecture:** Preserve the existing rich Core engineering models and make Study Preparation the sole interpreter of engineering units/bases. Preparation emits immutable, detached numerical snapshots; numerical builders/solvers consume only those snapshots; results are converted back to engineering meaning outside the numerical layer. Reuse the existing `PerUnitSystem`, canonical endpoint resolver, network topology, model classes, and solver contracts rather than introducing parallel managers or generic abstractions.

**Tech Stack:** Python, dataclasses, NumPy/SciPy sparse numerical structures, existing GridForge Core analysis/solver/model layers, existing repository test framework.

**Spec:** User-provided “GridForge GF-AUD-210–220 Remediation Implementation Plan” and the authoritative GridForge V2 architecture/rules supplied in the conversation.

## Global Constraints

- Core owns electrical truth; Application controls mutation; UI presents and edits through controlled commands.
- Core must remain independent of Qt/UI/plugins.
- Analysis must not mutate the authoritative Network.
- Numerical solvers consume prepared numerical snapshots, not live engineering objects.
- `YBusBuilder` must be numerical-only and must not interpret engineering units, bases, or live Core models.
- Reuse the existing `PerUnitSystem`; do not introduce another generic per-unit system.
- Reuse the existing canonical terminal resolver; do not create a second endpoint abstraction.
- No UniversalBranchManager, EngineeringNetworkManager, NumericalNetworkManager, MegaModel, or equivalent duplicate orchestration layer.
- Line authoritative quantities are engineering `resistance_ohm`, `reactance_ohm`, and `shunt_susceptance_siemens`, with applicable length/rating/sequence data.
- Cable authoritative data remains physical engineering truth, including length, rated data, positive/zero-sequence R/X/B; ambiguous legacy `r/x/b` must not be guessed.
- Transformer impedance basis must be explicit; ambiguous transformer impedance must be rejected or migrated only with authoritative metadata.
- No Cable double-conversion.
- Persistence preserves engineering truth, not YBus/ZBus/Jacobian/solver arrays.
- Tests may be added or updated for every changed contract, but **tests must not be executed during this remediation cycle unless the user explicitly authorizes execution**.
- Do not add future Harmonics, OPF, SCOPF, EMT, GPU, detailed inverter fault models, detailed AVR/governor/PSS, or advanced motor dynamics unless an existing active implementation is demonstrably broken and in scope.
- Do not claim runtime correctness without runtime execution evidence.
